# Legacy Gym — نظام إدارة النادي الرياضي

تطبيق Windows Desktop كامل لإدارة نادٍ رياضي، باللغة العربية (RTL)، يعمل محليًا **بدون إنترنت**،
بقاعدة بيانات SQLite محلية، وقابل للنقل على USB إلى أي جهاز.

![Legacy Gym](assets/logo.png)

---

## التشغيل السريع (أول مرة على جهاز التطوير)

```bash
npm install        # مرة واحدة فقط (يحتاج إنترنت أول مرة)
npm start          # تشغيل التطبيق
npm test           # تشغيل الاختبارات (194 اختبار)
npm run shortcut   # إنشاء اختصار على سطح المكتب مع الأيقونة
```

## حساب الدخول الافتراضي

| الدور | اسم المستخدم | كلمة المرور |
|-------|--------------|-------------|
| مدير Admin | `Kamal` | `123456` |

النظام يبدأ **فارغًا تمامًا** (بدون مشتركين أو منتجات أو أي بيانات) — كأنه مثبّت لأول مرة.
حسابات المستخدمين (مدراء وموظفون) تُدار بالكامل من: **الإعدادات ← إدارة المستخدمين**.

> **مهم قبل التسليم:** غيّر اسم المستخدم و/أو كلمة مرور المدير من صفحة **الإعدادات ← إدارة المستخدمين ← حسابي**.

## بناء نسخة جاهزة للتسليم (exe)

```bash
npm run dist
```

ينتج مجلد `dist/win-unpacked/` بداخله `LegacyGym.exe` — هذا هو البرنامج النهائي.

لإنشاء مثبّت NSIS (اختياري):

```bash
npm run dist:installer
```

## طريقة التركيب الكاملة على لابتوب الزبون (خطوة بخطوة)

النظام **لا يحتاج تثبيت (Installer)** — هو برنامج محمول (Portable): تُنسخ مجلد واحد، وتشغّله.
لا يحتاج إنترنت إطلاقًا لا أثناء النسخ ولا أثناء الاستخدام اليومي.

### الخطوة 1 — تجهيز الملفات (على جهازك، قبل الذهاب للزبون)

```bash
npm run dist
```

يُنشئ هذا مجلد `dist/win-unpacked/` — هذا هو **البرنامج الكامل الجاهز للتسليم**. تأكد أن مجلد
`data/` **غير موجود** بداخله قبل النسخ (إن وُجد، احذفه) — حتى يبدأ النظام فارغًا تمامًا عند أول
تشغيل عند الزبون. انسخ مجلد `dist/win-unpacked` بالكامل إلى USB.

### الخطوة 2 — النسخ إلى جهاز الزبون

1. أدخل الـ USB في لابتوب الزبون.
2. انسخ مجلد `win-unpacked` بالكامل إلى القرص المحلي (وليس التشغيل من داخل الـ USB مباشرة، لتفادي البطء).
3. أعد تسمية المجلد إلى `LegacyGym` وضعه في مكان واضح، مثلًا:
   ```
   C:\LegacyGym\
   ```
4. تأكد أن كل الملفات نُسخت (خصوصًا `LegacyGym.exe` ومجلد `resources` — لا تنسخ ملفًا واحدًا فقط).

### الخطوة 3 — التشغيل الأول والتفعيل

1. افتح مجلد `C:\LegacyGym\` وشغّل `LegacyGym.exe` بالنقر المزدوج.
2. سيظهر تحذير Windows SmartScreen في بعض الأجهزة (لأن البرنامج غير موقَّع رقميًا) — اضغط
   **"مزيد من المعلومات" (More info)** ثم **"تشغيل على أي حال" (Run anyway)**. هذا طبيعي وآمن،
   يحدث لأي برنامج جديد غير مسجَّل لدى Microsoft.
3. **شاشة التفعيل (مرة واحدة فقط لكل جهاز):** ستظهر شاشة تعرض **رقم هذا الجهاز (Machine ID)**
   بالشكل `IRON-XXXX-XXXX-XXXX-XXXX`. هذا التفعيل يمنع نسخ النظام إلى جهاز آخر. لتفعيله:
   - على **جهازك أنت** (وليس جهاز الزبون)، شغّل مولّد الأكواد بكلمة مرورك السرية:
     ```
     node tools/keygen.js IRON-XXXX-XXXX-XXXX-XXXX "كلمة-مرورك-السرية"
     ```
   - انسخ كود التفعيل الناتج، والصقه في خانة "كود التفعيل" على جهاز الزبون، ثم اضغط **تفعيل**.
   - التفعيل **مدى الحياة** لهذا الجهاز — لا تاريخ انتهاء، ولا يتكرر عند كل تشغيل.
4. بعد التفعيل، سينشئ البرنامج تلقائيًا مجلد `data\` بجانب `LegacyGym.exe` (قاعدة البيانات
   الفارغة + `config.json` + مجلد `backups`). لا حاجة لأي إعداد يدوي.
5. تظهر شاشة تسجيل الدخول — سجّل دخول بحساب المدير:
   - اسم المستخدم: `Kamal`
   - كلمة المرور: `123456`
6. **غيّر كلمة المرور فورًا** من: الإعدادات ← إدارة المستخدمين ← حسابي (انظر التحذير أدناه).

> **ملاحظة أمنية (للمطوّر فقط):** قبل أول تسليم حقيقي، شغّل مرة واحدة
> `node tools/license-setup.js "كلمة-مرورك-السرية"` لتوليد مفتاحك الخاص، ثم أعد البناء
> (`npm run dist`). ملف المفتاح الخاص `tools/license-private-key.pem` هو سرّك المطلق — لا
> يُسلَّم للزبون أبدًا ولا يُوضع على جهازه (مستبعَد تلقائيًا من نسخة الزبون).

### الخطوة 4 — إنشاء اختصار على سطح المكتب

أسهل طريقة (بدون أي أدوات):
1. كليك يمين على `LegacyGym.exe` داخل `C:\LegacyGym\`.
2. اختر **إرسال إلى** ← **سطح المكتب (إنشاء اختصار)**.
3. غيّر اسم الاختصار على سطح المكتب إلى "Legacy Gym" إذا رغبت.

الأيقونة تكون تلقائيًا شعار Legacy Gym الرسمي (مدمجة داخل الملف التنفيذي نفسه، لا حاجة لأي إعداد إضافي).

### الخطوة 5 — تجربة سريعة قبل تسليم الجهاز للزبون

- أضف مشتركًا تجريبيًا واحدًا، سجّل بيع منتج، افتح الصندوق اليومي، تأكد أن كل شيء يعمل.
- **ثم احذف هذا الاختبار** (أو الأفضل: أعد تصفير البيانات بالكامل بعد الاختبار — انظر القسم
  التالي "قاعدة البيانات — الموقع الدقيق وإعادة الضبط") حتى يستلم الزبون نظامًا فارغًا تمامًا.

### ملاحظات مهمة

- **لا حاجة لتثبيت** Node.js أو أي برنامج آخر على جهاز الزبون — كل ما يلزم مضمَّن داخل مجلد
  `win-unpacked` (بما في ذلك محرك التشغيل Electron نفسه).
- **لا حاجة للإنترنت** لا للتثبيت ولا للاستخدام اليومي — قاعدة بيانات محلية بالكامل (SQLite).
- **لنقل النظام لاحقًا لجهاز آخر:** انسخ مجلد `LegacyGym` بالكامل (وليس فقط ملف الـ exe).
- **لنقل البيانات فقط** (بدون إعادة تثبيت البرنامج) من جهاز لآخر: انسخ مجلد `data\` بالكامل
  (فيه `ironcore.db` و`backups\`) والصقه بجانب `LegacyGym.exe` في الجهاز الجديد.
- **النسخ الاحتياطي يبدأ تلقائيًا** من أول يوم استخدام — نسخة واحدة يوميًا، تُحفظ آخر 30 نسخة.

> **تحذير أمني قبل التسليم:** كلمة مرور المدير الافتراضية (`Kamal`/`123456`) معروفة لأي شخص يقرأ
> هذا الملف — **غيّرها إلزاميًا** من داخل النظام قبل تسليم الجهاز للزبون فعليًا (الإعدادات ←
> إدارة المستخدمين ← حسابي ← تغيير كلمة المرور).

## ملف الإعدادات القابل للتعديل

يوجد في `data/config.json`:

```json
{
  "autoBackup": true    // نسخة احتياطية تلقائية يوميًا عند فتح البرنامج
}
```

باقي الإعدادات (اسم النادي، الأسعار، سعر صرف الليرة، مجلد النسخ الاحتياطي…) من داخل
التطبيق: **الإعدادات** (حساب المدير).

### الشعار الرسمي
الشعار الرسمي هو `assets/logo.png` ويُستخدم في: شاشة التحميل، تسجيل الدخول،
الـ Sidebar، ترويسة تقارير PDF، أيقونة النافذة، وأيقونة اختصار سطح المكتب.
لتحديثه: استبدل `assets/logo.png` ثم شغّل `npx electron tools/render-icon.js`
لإعادة توليد `icon.ico`، وأعد البناء.

### الاشتراك الشهري
يُحسب بالشهر التقويمي: اشتراك بتاريخ 03/07 ينتهي 03/08 (نفس اليوم من الشهر التالي)،
وليس بعد 30 يومًا فقط. إذا لم يوجد اليوم نفسه في الشهر التالي (مثل 31) يُعتمد آخر يوم في الشهر.

## الصلاحيات

| الميزة | مدير | موظف |
|--------|------|------|
| لوحة التحكم | كاملة | بدون أرقام المصاريف/الصافي |
| المشتركين + الاشتراكات | نعم | نعم |
| المبيعات | كل الموظفين | مبيعاته هو خلال اليوم فقط |
| المنتجات والمخزون | نعم | نعم |
| الصندوق اليومي | كامل + أي يوم + تصدير | **اليوم الحالي فقط** (لإقفال الدوام) — نفس مجموع اليوم الذي يراه المدير |
| المصاريف / الموظفون / الرواتب | نعم | لا |
| التقارير الشهرية/السنوية | نعم | لا |
| النسخ الاحتياطي / الإعدادات / إدارة المستخدمين / سجل العمليات | نعم | لا |
| تعديل/حذف العمليات | دائمًا (كل تعديل يُسجَّل قبل/بعد) | **سجلاته هو فقط وخلال ساعتين** من إدخالها |
| حذف مشترك | حذف نهائي خلال 24 ساعة، أرشفة/إلغاء بعدها (مع استعادة) | لا |

### إدارة المستخدمين (الإعدادات ← إدارة المستخدمين)

- **حسابي:** تغيير اسم المستخدم الخاص بالمدير الحالي، وتغيير كلمة المرور (يتطلب كلمة المرور
  الحالية + تأكيد الجديدة، 6 أحرف على الأقل) — بعد تغيير كلمة المرور يُسجَّل الخروج تلقائيًا
  لإعادة الدخول بالكلمة الجديدة.
- **إنشاء/تعديل مستخدم:** الاسم الكامل، اسم المستخدم، الهاتف، الوظيفة، الصلاحية (مدير/موظف).
- **إعادة تعيين كلمة مرور** أي مستخدم بدون معرفة كلمته القديمة.
- **تفعيل/إيقاف** الحساب — الحساب الموقوف لا يمكنه تسجيل الدخول.
- **حذف مستخدم:** حذف نهائي إذا لم يكن له أي سجل عمليات (مبيعات/اشتراكات/مصاريف/رواتب)،
  وإلا يُوقَف تلقائيًا بدل الحذف للحفاظ على البيانات المالية المرتبطة به.
- لا يمكن إيقاف أو حذف أو تخفيض صلاحية **آخر حساب مدير فعّال** في النظام (حماية من فقدان الوصول).
- بحث (بالاسم/اسم المستخدم/الهاتف) وفلاتر (الكل، مدراء، موظفون، ناشط، موقوف).
- كل عملية (إنشاء، تعديل، تغيير اسم مستخدم/صلاحية/كلمة مرور، إيقاف/تفعيل، حذف) تُسجَّل في
  سجل العمليات دون أي حفظ أو عرض لكلمة المرور نفسها.

- **البيع لمشترك:** خانة المشتري في المبيعات هي بحث ذكي (اسم/شهرة/هاتف/ID) — لا يمكن ربط بيع
  باسم غير موجود؛ خيار "زبون خارجي / بدون مشترك" متاح دائمًا، ويُحفظ `member_id` مع العملية.

- كل عملية (بيع، دفعة، تجديد، إيقاف مؤقت، تعديل، حذف…) تُسجَّل في **سجل العمليات** باسم الموظف والوقت.
- دفعة على اشتراك قديم من موظف تُعلَّم في السجل «بانتظار مراجعة المدير».
- إذا تغيّر وقت الجهاز إلى الوراء يظهر تحذير للمدير عند الدخول ويُسجَّل في السجل.

### منع تكرار المشتركين

قبل إضافة مشترك جديد يتحقق النظام تلقائيًا من الاسم الكامل ورقم الهاتف:

- **نفس الاسم + نفس رقم الهاتف (أو كلاهما بدون هاتف):** يُمنع الإنشاء نهائيًا، وتظهر رسالة
  "هذا المشترك موجود بالفعل" مع خيارين: **فتح بيانات المشترك** أو **تجديد الاشتراك** — لا يُنشأ
  أي مشترك مكرر أبدًا.
- **نفس الاسم فقط (هاتف مختلف أو غير موجود على أحد الطرفين):** تظهر رسالة تحذير
  "يوجد مشترك بنفس الاسم بالفعل." مع خيار المتابعة (حالة واقعية: شخصان مختلفان بنفس الاسم).
- **التجديد لا يُنشئ مشتركًا جديدًا أبدًا:** زر "تجديد الاشتراك" (من قائمة المشتركين، أو من داخل
  ملفه الشخصي، أو من نافذة التكرار) يضيف سجل اشتراك جديد مرتبطًا بنفس رقم المشترك (Member ID) فقط
  — مع الحفاظ الكامل على كل الاشتراكات والدفعات والمبيعات وسجل العمليات السابقة لهذا المشترك.

### الصندوق اليومي — موحّد بين المدير والموظف

مجموع صندوق اليوم واحد للجميع: كل عمليات اليوم (مبيعات، دفعات اشتراكات، مصاريف) تُحسب حسب
**تاريخ العملية فقط** بغض النظر عمّن أدخلها — إذا باع المدير بضاعة اليوم يظهر ذلك في صندوق
الموظف، والعكس صحيح، والمجموع النهائي مطابق تمامًا عند الاثنين. عمود **"أدخل بواسطة"** في جدول
الصندوق يوضح اسم من قام بكل عملية (مدير أو موظف). الصندوق للموظف يعرض دائمًا **اليوم الحالي فقط**
(لا يمكنه تغيير التاريخ ولا رؤية تقارير شهرية/سنوية)، وهو للقراءة فقط لا يحتوي أزرار تعديل أو حذف
لأي أحد. يوم جديد = صندوق جديد يبدأ من صفر تلقائيًا (يُحسب من تاريخ اليوم في كل مرة، بدون أي
ترحيل لمجموع الأمس)؛ بيانات الأيام السابقة تبقى محفوظة وتظهر للمدير عبر التقارير أو باختيار تاريخ
مختلف في الصندوق.

## تنسيق التاريخ — موحّد على DD/MM/YYYY في كامل النظام

كل تاريخ يظهر للمستخدم في أي مكان (الجداول، النوافذ المنبثقة، شريط التاريخ أعلى البرنامج، PDF،
Excel، الطباعة، سجل العمليات، النسخ الاحتياطي...) يُعرض دائمًا بصيغة **يوم/شهر/سنة** (مثال: `03/07/2026`)
— ولا يظهر أي تاريخ بصيغة شهر/يوم/سنة (MM/DD/YYYY) في أي شاشة. التخزين الداخلي في قاعدة البيانات
يبقى ISO (`YYYY-MM-DD HH:mm:ss`) كما هو أفضل للفرز والحسابات، ويُحوَّل فقط عند العرض عبر دالتين
مركزيتين في `Logic.arDate` و`Logic.arDateTime`. شريط التاريخ أعلى البرنامج يعرض مثلًا
"الاثنين 06/07/2026" فوق الساعة "18:21".

**حقول اختيار التاريخ (Date/Month Picker):** لا يمكن الاعتماد على إعدادات لغة النظام وحدها لضبط شكل
حقل التاريخ الأصلي في Windows، لأن الترتيب المعروض (يوم/شهر أو شهر/يوم) في هذا الحقل تحديدًا يتبع
**إعدادات المنطقة في جهاز العميل نفسه** (Control Panel)، وليس لغة التطبيق — قد يختلف من جهاز لآخر
عند التسليم. لذلك بُني حل مضمون 100%: الحقل الأصلي (Native) يبقى يعمل بالكامل خلف الكواليس (التقويم
المنبثق، لوحة المفاتيح، والقيمة المخزَّنة تبقى ISO)، لكن يُخفى نصه الخاص بالكامل خلف طبقة معتمة، ويُرسم
فوقه نص من صنع البرنامج نفسه بصيغة DD/MM/YYYY بأرقام إنجليزية دائمًا (عبر `UI.wrapNativeDateInput` في
`ui.js`) — هذا يضمن ثبات الشكل على أي جهاز Windows بغض النظر عن إعداداته الإقليمية. لغة التطبيق
داخليًا مضبوطة على `en-GB` (وليس العربية) لأن اللغة العربية تسبب عرض الأرقام بالهندية العربية
(٠١٢٣...) بدل الأرقام الإنجليزية في الحقول الأصلية وحتى في حقول الأرقام العادية.

## النسخ الاحتياطي

- تلقائي: يوميًا عند أول فتح للبرنامج (يحتفظ بآخر 30 نسخة).
- يدوي + استرجاع + تغيير مجلد الحفظ: من صفحة **النسخ الاحتياطي**.
- قبل أي استرجاع يُؤخذ Backup أمان تلقائي للبيانات الحالية.

## التصدير

- **Excel (CSV بترميز عربي سليم):** المشتركين، الاشتراكات، المصاريف، الصندوق، التقارير، سجل العمليات.
- **PDF:** الصندوق اليومي والتقارير الشهرية/السنوية (بترويسة الشعار).

## قاعدة البيانات — الموقع الدقيق وإعادة الضبط

- **اسم الملف:** `ironcore.db` (قاعدة SQLite واحدة، عبر محرك sql.js — بدون خادم، بدون إنترنت).
- **المسار أثناء التطوير:** `GYM/data/ironcore.db` (بجانب مجلد `main/`).
- **المسار بعد التسليم (النسخة المبنية):** `data/ironcore.db` **بجانب ملف `LegacyGym.exe` نفسه**
  أينما نسخه العميل (مثلًا `C:\LegacyGym\data\ironcore.db`) — محمول بالكامل، لا يعتمد على مسار ثابت.
- **مجلد النسخ الاحتياطية:** `data/backups/` (بجانب `ironcore.db` نفسه).
